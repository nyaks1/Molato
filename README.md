# Molato

WTC-SULJLKF2

Molato (Setswana: offense / fault / case) — a deliberately vulnerable Flutter fintech app paired with a detector that turns every privacy leak into The Docket: a charge sheet mapping each violation to the exact POPIA section it breaks.

## What this is

Two parts, one story:

- **The Offense** — `/app` — a small Flutter fintech demo app that deliberately leaks PII (names, account numbers, transaction data) into device logs. This maps to OWASP Mobile Top 10 — M6: Inadequate Privacy Controls.
- **The Docket** — `/detector` — a Python/Bash script that reads the device logs, flags every leak, and writes a report (`DOCKET.md`) mapping each finding to the specific section of POPIA it violates (e.g. Condition 7 — Security Safeguards).

The point isn't "here's a vulnerable app." The point is: here's proof I can find the offense and write the case against it.

## Why it exists

Built as a solo proof-of-work for the WeThinkCode_ Cybersecurity elective selection — original work, public repo, steady commit history, 5–10 min demo video.

## OWASP mapping

| OWASP M6 sub-issue | Where it lives in the app |
|---|---|
| Sensitive data in logs | `app/lib/services/insecure_logger.dart:6` (login), `:16` (tx), `:21` (logout) |
| No log redaction layer | `app/lib/services/insecure_logger.dart` — whole `InsecureLogger` class |
| Debug logging left in release build | bare `print()` in `InsecureLogger` (linter: `avoid_print`) |

## POPIA mapping (generated by the Docket, not hand-written)

Citations come from the official Act 4 of 2013 (gov.za). Condition 5 is **Information quality** — purpose sits in Condition 3.

| Condition | What's broken | Evidence |
|---|---|---|
| Condition 7 — Security safeguards (s.19) | PII persisted in plaintext logs | docket.json entries #001–#003 |
| Condition 3 — Purpose specification (s.13) | Logged fields exceed what the feature needs | docket.json entries #001–#003 |

## POPIA standing gate

- **Collected:** demo account name, account number, transaction amount — synthetic/dummy data only, no real user data.
- **Hosted:** nowhere. This is a local, on-device demo — no cloud backend, no africa-south1 bucket, nothing leaves the machine. That's part of the point: even a fully local app leaks if logging isn't controlled.
- **Deleted:** logs cleared on app uninstall / `adb logcat -c`; no persistence layer beyond the local log buffer.

## Architecture

```
molato/
├── app/            # Flutter app (the offense)
│   └── lib/
├── detector/        # Python/Bash detector (the docket)
│   ├── docket.py
│   ├── run.sh
│   └── fixtures/     # offline logcat samples for self-test
├── docket.json       # generated findings, machine-readable
├── DOCKET.md          # generated findings, human-readable
└── README.md
```

## Running it

```bash
# 1. Run the vulnerable app on an emulator/device
cd app && flutter run

# 2. Reproduce the leak (trigger a transaction)
# 3. Pull logs and run the detector
cd ../detector
./run.sh
# → writes docket.json + DOCKET.md
```
